# Gateway integration readiness

Sonnely currently publishes its customer-facing inference gateway from `fathom-relay`. The existing manual UsageMax export reads up to 100 settled requests and sends the settled customer charge through the local collector format. The first automatic integration keeps that export available and introduces project-scoped ingestion and reporting. Sonnely's ledger continues to own balances, credit holds, settlement, and payouts.

| Brief area | Existing capability | First slice and remaining work |
| --- | --- | --- |
| Server ingestion | Scoped device collectors, native and OTLP JSON batches, replay protection, limits and diagnostics | Project-specific ingest and reporting keys, a bounded receipt API, sender outbox and generated request types. Item validation reports, general-purpose backfill and eval client methods remain follow-ups. |
| Inference traces | Logical request IDs, trace and span IDs, optional latency and first-token timing | Receipt-embedded gateway spans cover reservations, observed provider attempts, settlement, and billing recovery. Provider internals and independent service traces require additional instrumentation. |
| Token accounting | Input, output, cache, reasoning and unclassified accounting | Preserve supplied receipt dimensions and missing values. Provider normalization by adapter, attempt and billed request counts, and non-token units remain follow-ups. |
| Reporting | Workspace views, public aggregate stats, data exports and WorkOS membership | Private 31-day report with day, provider and model groups, latency percentiles, and cost-evidence coverage across up to 2,000 newest retained receipts. Higher-volume materialized analytics, exports, and saved views remain follow-ups. |
| Costs and reconciliation | Distinct financial bases, provider imports and monthly variance views | Separate customer charges, known provider costs and covered margin. Sonnely administrators can reconcile normalized statement lines by reference and publish invoice-confirmed receipt revisions. Automated provider statement import and financial close remain follow-ups. |
| Operational alerts | Workspace budgets, notifications and coverage checks | Scheduled, deduplicated private alerts track provider attempts, latency, and pending billing. External notifications and customizable rules remain follow-ups. |
| Evaluations | Outcome labels for agent telemetry | Versioned synthetic cases, local budget gating in CI, live measurement, and opt-in publication into a project. The Gateway dashboard shows retained runs and case regressions against a compatible hosted baseline. Scheduled live runs and custom datasets remain follow-ups. |
| Compute | Sonnely tracks compute runs and settlement separately | UsageMax compute ingestion, utilization and stale-run alerting remain follow-ups. |
| Privacy and trust | Workspace membership, RBAC, retention, audits and content allowlists | Private project keys, receipts, and eval runs bypass public projections. Hosted runs contain per-case metrics and pass/fail outcomes and follow workspace retention. Customer-scoped project permissions and content-based evaluation need separate acceptance. |
| Sonnely acceptance | Manual export and the Admin ledger | Integrate at the shared settlement transaction, send asynchronously, and read reports after Admin authorization. Release evidence requires a deployed settled request, replay, revision and isolation checks. |

The [gateway integration guide](https://docs.usagemax.com/gateway) describes the receipt contract and hosted eval publication. Track deployment acceptance separately from source and fixture tests.
